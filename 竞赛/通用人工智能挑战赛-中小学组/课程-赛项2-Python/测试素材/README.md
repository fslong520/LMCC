## 2026-09 数据扩充记录（Wikimedia 拉取）

流程：`fetch_wikimedia.py` 按 Commons 分类（Oranges/Tangerines/Apricots/
Persimmons/Pumpkins 等 9 个）拉 90 张 → 视觉模型逐张质检 → 人工复核空判样本
→ 最终 59 张入集、31 张淘汰（淘汰率 34%：绘画/人物/风景/混杂果盘/标牌/错误类别）。

**两次质检的意义**：网络图源噪声率同样 ~1/3——机器拉图省时间，但
"逐张看图"这道工序不能省，这与训练台"健康度检查"同构。

## 2026-09 数据清洗记录（重要教训）

初版 orange/not_orange 各 40 张，但**每类混入 12 张标注噪声**——orange 里有蛋糕、
加州地标牌、木星照片、冰箱、风景；not_orange 里有风景、人物、店铺等与"橙色调
近物"无关的图。当时特征/模型反复调优都撞在 ~62% 的墙上；加纹理（LBP）、边缘
方向、HOG、中心裁剪等新维度**全部无效**。逐张看图清洗后，同一套代码：

| 数据 | 最佳组合 | 5折CV |
|:-----|:---------|:-----:|
| 清洗前（40+40，含噪声） | A_basic16 + SVM | 62.5% |
| 清洗后（28+28，纯净） | E_texture(LBP+梯度) + SVM | **65.9%**（且标准差减半） |
| 清洗后 · 易例对照 | A_basic16 + 决策树 | 92.9% |

**结论（比"加维度"更值钱）**：调模型前先看数据。标注错的数据里，噪声样本会把
决策边界搅乱——特征再好也学不出规律。这正是识物工坊"健康度检查"要做的事：
**类别错误、无关图在采样时就该剔除**。课上可用 `_噪声图待审/` 的图现场演示
"为什么这张图会毁掉模型"。

## 对照实验：数据难度 vs 精度

扩充后（115 张）同口径重测：最佳 **D_combined + 随机森林 67.8%**、A+SVM 67.8%、
纹理 SVM 53.0%（难例增多后单靠麻点统计不够，颜色+空间组合更稳）、
CNN 同口径 61.7%。对照 28+28 时代：SVM 66.1%、CNN 59.2%——
**加真数据 SVM +1.7%、CNN +2.5%**，且各折方差收窄。

| 非橙子类别 | 测试精度（留出法） | 说明 |
|:----------|:-------:|:-----|
| 难例（`not_orange/`） | ~60-68% | 难例本就难分 |
| 普通（`not_orange_easy/`） | 92.9% | 假阴性 0 |

**结论**：数据是模型上限。非橙子越"像橙子"（难例越多），模型越难分。难例决定
区分度：想拿高分要"补得准"，但也须知难例本就会压低表面精度。

## 用途

- **采样练习**：学生用 Python（第1/3讲）遍历、统计、去重这两类
- **健康度检查**：观察重复/模糊/类别错误的图（第3/4讲）——`_噪声图待审/` 是现成反例教具
- **测试模型**：识物工坊训练后用"未训练"的新图测（第5讲）
- 两类数量接近 + 非橙子含难例——正是识物工坊的高分备赛数据形态
