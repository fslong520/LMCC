离线重放已能**精确复现**两任务的云端成绩（任务三 98.0、任务二 98.2，时长误差 <0.2 s）。

### 2. 任务二基线已在「贴边直穿」，而非沿路网折线绕行

- 任务三基线最小走廊余量较大 → 沿折线逐节点走，绕行比 1.45，故有 14.5 s 可压。
- **任务二基线最小余量仅 0.0015 单位**（贴着走廊边界），说明它已在走廊内走直线捷径。
  这解释了为何任务二可压缩空间远小于任务三。

### 3. 任务二的包裹顺序并非最优 —— 这是主要机会

用 DP（状态 = 已过检查点数 × 已送达集合 × 手持物 × 位置）枚举后：

- 基线顺序的直线距离和 = **153.50 u**
- 最优顺序的直线距离和 = **126.38 u**（省 27.12 u）

最优顺序：

```
start -> cp#0 -> cp#1 -> cp#2 -> grab(target-1) -> cp#3 -> cp#4
      -> drop(target-1) -> grab(distractor-1) -> drop(distractor-1)
      -> grab(distractor-2) -> drop(distractor-2) -> cp#5
      -> grab(target-2) -> drop(target-2) -> goal
```

即：**先巡完前 3 个检查点再取第一件目标物**，把两件混淆物的处理插到 cp#4 与 cp#5 之间。

### 4. 时间下界（乐观，假设全部可直线）

| 项 | tick |
|---|---|
| 行驶（126.38 u） | 5056 |
| 转向（15 × 13 下限） | 195 |
| 交互（4 抓 + 4 放） | 288 |
| **合计** | **5539 = 110.8 s** |

满分线 6240 tick = 124.8 s。**下界低于满分线 701 tick，故 100 分理论上可达**，
但只有 3/15 段能真正直行（走廊是弯的），真实距离必大于 126.38 u。

## 关键约束（不可违反）

1. **检查点按索引顺序**判定（`core.js:2306` 按 `nextCheckpointIndex` 递增，线段穿圆即算通过）。
2. **抓放位姿**决定 grab/release 成败：
   - `forward ∈ [0.38, 1.35]`、`lateral ≤ 0.38`（`auth_scene.json` 的 `inter.grab`）
   - 候选按「到车距离」升序取第一个进入锥内者（`core.js:3118-3120`）；
     若障碍物更近且落入锥内，会被判 `not_grabbable`。
3. **混淆物释放点须在路外**（`placementRule: road-edge-clearance`，路缘净空 ≥ 0.2）。
4. **转向角度必须在 1~360 度之间**（平台前端校验；`core.js` 内核不含此下限，
   故离线重放须自行补上，否则会放过平台实际拒绝的微角度转向）。
5. **障碍物只在 `inter.packages` 里**，`auth.packages` 不含障碍物。
