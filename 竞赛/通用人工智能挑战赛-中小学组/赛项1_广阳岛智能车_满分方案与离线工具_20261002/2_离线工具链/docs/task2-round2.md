在「检查点必须按 0→5 依次经过」的硬约束下，把 4 件包裹的抓放时机交给 Dijkstra 搜索，
代价用真实 tick 模型（经真机 179 条指令验证）。

```
start → cp#0 → cp#1 → cp#2 → grab(target-1) → cp#3 → cp#4 → drop(target-1)
      → grab/distractor-1 → grab/distractor-2 → cp#5 → grab(target-2) → drop → goal
```

要点：**先巡完 cp#0~cp#2 再取第一件目标物**，手持 target-1 巡 cp#3、cp#4 后才投仓。

## 当前卡点（诚实记录）

图的解算结果 **138.9s 无法在重放中复现**——重放时
① 出现 12~14 次越界（超出走廊 0.01~0.04u）；
② 首次抓取被拒（`behind`/`side`），车实际位置与解算偏差 1.2~1.6u；
③ 仿真报告撞上 `package-stack:0.51,4.432`（即 target-1 的包裹堆）。

已定位到的一处机制性原因：
- 我看到解算路径中出现 `right_angle(180)` + `forward` 的**掉头折返**（findings 里叫「去又回」），
  这在 tick 模型里便宜（180°仅 57 tick），但真实执行会撞上刚经过的包裹堆。
- 已加「禁止立即折返」「单次转向上限 120°」两道约束，掉头消失，但越界与抓取失败仍在。

## 判断

任务二瓶颈与任务三不同：任务三基线沿路网折线走（绕行比 1.45），拉直即可省 14.5s；
任务二基线**已在走廊内贴边直穿**（最小余量 0.0015），故「拉直」几乎没有余量可用，
真正的空间在**顺序重排**（省 27u 直线距离）——但重排后的路径无法用当前图复现，
说明图的碰撞判定与真实仿真在**障碍物邻域**仍不一致。

下一步应做的是：把图搜索产出的路径**逐段用仿真同构的射线判定复核**，
对齐后再谈顺序重排，而不是继续调生成器参数。
